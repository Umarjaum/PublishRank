### Traffic measurement and privacy caveats

The analytics subsystem is distinct from external Search Console data. Search Console clicks and impressions are Google's reporting metrics; the plugin's tracker measures only visits it observes after activation and cannot recreate past traffic. Even if IPs and cookies are not retained, visitor recognition is an approximation affected by daily rotation, browsers, blocked requests and privacy settings. The ZIP README makes strong privacy/metric claims; they need runtime verification under representative proxy, consent, DNT and bot conditions before being represented as guarantees. Do not describe unique visitors as perfectly identified or imply every browser is tracked.

### Access Shield claims to keep bounded

Source organization supports Access Shield as an integrated security feature, not a stand-alone managed security perimeter. Do not claim an enterprise WAF, DDoS mitigation, complete attack prevention, tamper-proof/tamper-evident security logs unless current implementation cryptographically establishes that property, or authentication methods absent from source. Security log/statistics storage includes security-event data, including IP fields in schema; that must not be confused with the analytics tracker’s separate no-IP claim (`src/Core/Database.php`).

## REST, CLI, and database inventory

- **WooCommerce REST:** `src/WooCommerce/RestApi.php` registers routes under `publishrank/v1`: `/woocommerce/settings`, `/woocommerce/audit`, `/woocommerce/products/{id}`, `/woocommerce/products/{id}/schema`, `/woocommerce/gtin/validate`, `/woocommerce/feed`, and `/woocommerce/feed/rotate-key`. Most administrative routes use capability checks. See callbacks for method and permission specifics.
- **Analytics REST:** `src/Analytics/Tracker.php` registers tracking endpoint; `src/Admin/AnalyticsPage.php` registers admin reporting endpoints. `src/Google/LiveSync.php` contains Search Console live-sync endpoints. Other API groups include AI, redirect, roles, schema library and robots; see respective classes or run source search for `register_rest_route`.
- **WP-CLI:** `src/CLI/WooCommerceCommand.php` registers `wp publishrank woo`; `ShieldCommand.php` registers `wp publishrank shield`; `RedirectCommand.php` registers `wp publishrank redirect` and `wp publishrank 404`; `PublishRankCommand.php` registers `wp publishrank sitemap`. Command existence does not mean commands were executed or all environments support them.
- **Tables:** `src/Core/Database.php` defines versioned/idempotent `dbDelta()` creation. Relevant 2.24 additions include `traffic_daily` and `traffic_seen`; broader existing schemas include security attempts/logs, 404 records/daily aggregates, redirect rules/groups/history, AI bot/citation data, and feed stats. Table names are prefixed dynamically. Not every feature is table-backed; product data is chiefly WooCommerce post metadata. No DB was created or migrated during this audit.

## Bottom line

This exact 2.24.0 archive contains substantial code for the stated analytics, WooCommerce SEO, Access Shield, theme cleanup/masking and earlier publisher/SEO subsystems. The strongest evidence is the concrete implementation tree and schema/route registrations cited above. However, the release itself explicitly disclaims production readiness, PHP 7.4 remains unverified, the referenced verification report is missing, and requested genuine feature screenshots are absent. Product pages/documentation should preserve these warnings, clearly label conditional or illustrative material, distinguish code presence from tested behavior, and avoid treating the master prompt's desired feature list as proof.
