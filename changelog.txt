= 2.9.43 =
* Fix (News sitemap): rebuilt the provider as a bounded, UTC-based query. It no longer uses the keyset cursor store or WP-Cron, so a new article appears on the next request instead of after a background job, and no 503 is returned for News.
* Fix: News publication window now compares `post_date_gmt` against UTC (previously a site-timezone relative date query), and `publication_date` is always the original publish time.
* Fix: titles are decoded and escaped exactly once (WordPress stores typographic entities such as &#8217;); articles with no title are skipped instead of emitted blank; `<news:language>` is normalised to an ISO 639 code (zh-cn / zh-tw for Chinese) and parenthetical text is removed from the publication name, per Google's specification.
* Fix: News entries are now excluded for noindex set by PublishRank, Yoast SEO or Rank Math, for password-protected posts, and for URLs that are empty or off-site.
* Change: `<news:genres>` and `<news:keywords>` are no longer part of Google's News sitemap specification and are emitted only if the `publishrank_news_emit_legacy_tags` filter returns true. Settings are unchanged.
* Fix: cache invalidation now also runs on status transitions (publish, trash, unpublish, scheduled publish) and when News eligibility, robots, title or canonical meta changes.
* Fix: cursor-backed sitemaps advance a bounded number of steps inline when a shard is requested, so a disabled or stalled WP-Cron can no longer leave a shard on HTTP 503; incomplete cursors that stop progressing for 24 hours restart automatically; overdue follow-up events are cleared.
* Fix: HTTP responses. Unknown or out-of-range sitemap URLs return 404, generation failures return 500 and are recorded, XML is always UTF-8, buffered output is discarded before the XML declaration, HEAD requests are supported, and WordPress canonical redirects can no longer rewrite sitemap URLs.
* Change: image and video sitemaps use 5,000 URLs per file (protocol limit remains 50,000 URLs / 50 MB; News stays at 1,000). Files over 50 MB are refused and reported instead of served.
* Added: Sitemap Health now shows News diagnostics (enabled, public URL, index membership, window, eligible count, XML validity, last generation, skip reasons, last error) and cursor / WP-Cron health.
* Added: LiveBlogPosting. Only posts explicitly set to the Live Blog Post schema type (or the live news format) are marked up; titles and categories containing "live" no longer trigger it. New Live coverage panel with coverage start/end and individually timestamped updates, emitted as liveBlogUpdate BlogPosting entries. Coverage times are never derived from the publish date.
* Fix: manual and auto-detected FAQ blocks no longer produce duplicate FAQPage nodes; FAQ answers are sanitised; the schema graph is de-duplicated (shared @id, identical FAQ sets, one primary article entity per page).
* Added: optional Speakable markup through the `publishrank_schema_speakable_selectors` filter (no selectors are invented).
* Attribution: the front-end source comment now names PublishRank SEO and links the official site. It is emitted once, only in front-end HTML (never admin, AJAX, REST, feeds, embeds or sitemaps), and is not stored in content. See docs/ATTRIBUTION.md for the WordPress.org guideline conflict.
